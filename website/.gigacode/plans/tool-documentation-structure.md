# План структуры документации по инструментам

## Текущая ситуация

Сайт уже содержит хорошую документацию, но инструменты описаны в общих файлах по категориям:
- `docs/tools/development-tools.mdx`
- `docs/tools/data-tools.mdx`
- `docs/tools/administration-tools.mdx`
- `docs/tools/exchange-tools.mdx`
- `docs/tools/debugging-tools.mdx`

Каждый файл содержит таблицу с описаниями инструментов, но нет отдельных страниц для каждого инструмента.

## Цель

Создать масштабируемую структуру, где каждый инструмент будет иметь свою страницу документации с возможностью добавления подробных руководств, API-спецификаций, примеров и скриншотов.

## Реализованные изменения

## Содержание файлов для каждого инструмента

### `intro.mdx` (обязательный)
- Краткое описание инструмента
- Назначение и принцип работы
- Системные требования (если есть)
- Скриншот интерфейса

### `usage.mdx` (опциональный)
- Подробное руководство пользователя
- Пошаговые инструкции по использованию
- Настройка параметров
- Примеры типичных задач

### `examples.mdx` (опциональный)
- Примеры кода (если применимо)
- Сложные сценарии использования
- Интеграция с другими инструментами

### `api.mdx` (опциональный)
- API вызовы (если есть)
- Методы программного вызова
- Примеры программного использования

## Преимущества новой структуры

1. **Масштабируемость** — легко добавлять новые инструменты
2. **Гибкость** — каждый инструмент может иметь разное количество страниц
3. **Удобство** — пользователь может быстро найти нужный инструмент
4. **SEO** — отдельные страницы для каждого инструмента
5. **Версионирование** — можно версионировать документацию по отдельным инструментам
