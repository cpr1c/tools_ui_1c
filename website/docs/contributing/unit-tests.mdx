# Модульные тесты

Для проверки кода подсистемы используются модульные тесты на фреймворке
[YAxUnit](https://github.com/bia-technologies/yaxunit) — тестовом движке для решений на платформе
1С:Предприятие (лицензия Apache 2.0).

## Где лежат тесты

Тесты находятся в отдельном расширении `src/МодульныеТесты/` (исходники в формате EDT):

```
src/МодульныеТесты/src/
├── CommonModules/УИТ_ТестГенераторКода/   # тесты общего модуля УИ_ГенераторКода
├── Catalogs/УИТ_ТестСправочник/           # тестовые данные
├── Documents/УИТ_ТестДокумент/
├── CommonTemplates/УИТ_ТестоваяКартинка/
└── ...
```

Расширение не входит в поставку — оно собирается и подключается только для запуска тестов.
Все объекты расширения имеют префикс `УИТ_`, тестовые данные создаются объектами `УИТ_Тест*`,
поэтому тесты не зависят от данных информационной базы.

:::info
Движок YAxUnit в репозитории не хранится. При подготовке базы он скачивается из
[релизов проекта](https://github.com/bia-technologies/yaxunit/releases) или подключается из файла,
указанного в параметре `--yaxunitpath`.
:::

## Как устроен тест

Тестовый модуль — общий модуль расширения `МодульныеТесты`, который экспортирует функцию
`ИсполняемыеСценарии()`. В ней регистрируются тестовые наборы и тесты, а сами проверки
оформляются отдельными экспортными процедурами.

```bsl
// Регистрирует тестовые наборы и тесты модуля.
//
// Возвращаемое значение:
//  ОбщийМодуль - модуль регистрации тестов, см. ЮТТесты
Функция ИсполняемыеСценарии() Экспорт

	ЮТТесты.ДобавитьТестовыйНабор("ГенераторКода.Примитивы", "ГенераторКода")
		.ДобавитьТест("БулевоВСтрокуКода")
		.ДобавитьТест("ЧислоВСтрокуКода")
		.ДобавитьТест("ДатаВСтрокуКодаБезВремени");

	Возврат ЮТТесты;

КонецФункции

// Проверяет преобразование булева значения в строку кода.
Процедура БулевоВСтрокуКода() Экспорт

	ЮТест.ОжидаетЧто(УИ_ГенераторКода.БулевоВСтрокуКода(Истина), "Истина")
		.Равно("Истина");

	ЮТест.ОжидаетЧто(УИ_ГенераторКода.БулевоВСтрокуКода(Ложь), "Ложь")
		.Равно("Ложь");

КонецПроцедуры
```

## Запуск тестов

:::tip
Для разработки в 1С:EDT удобно использовать [плагин YAxUnit](https://bia-technologies.github.io/yaxunit/docs/getting-started/edt-plugin/) —
он позволяет запускать и отлаживать отдельные тесты прямо из IDE.
:::

## Запуск в CI

Тесты запускаются в GitHub Actions при pull request в `develop` или `master`, если изменены
`src/Инструменты/**`, `src/МодульныеТесты/**` или `src/builder/**`:

- [`.github/workflows/run-tests-pr.yml`](https://github.com/cpr1c/tools_ui_1c/blob/develop/.github/workflows/run-tests-pr.yml) —
  собирает расширения, готовит базу командой `ubase` и передаёт её в матрицу запуска;
- [`.github/workflows/step-run-tests.yml`](https://github.com/cpr1c/tools_ui_1c/blob/develop/.github/workflows/step-run-tests.yml) —
  восстанавливает базу, запускает тесты и публикует отчёт.

Матрица запуска: Windows и Ubuntu, платформа 1С 8.3.27.2170, локаль `ru_RU`. Результаты оформляются
как JUnit-отчёт и публикуются в проверках pull request: красная проверка означает, что хотя бы один
тест не пройден.

## Соглашения

- Тестовый набор называется `<Модуль>.<Группа>`, имя теста совпадает с именем процедуры;
- проверяемый модуль вызывается по имени (`УИ_ГенераторКода.Метод(...)`), тест не должен зависеть
  от данных информационной базы;
- тестовые данные создаются объектами расширения `УИТ_Тест*`;
- тесты, изменяющие данные, регистрируются с `.ВТранзакции()` — изменения откатываются после теста;
- тестовый код документируется так же, как код подсистемы (см.
  [Правила оформления кода](/docs/contributing/coding-guidelines)).
