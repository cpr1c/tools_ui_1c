# Написание документации

Сайт документации построен на [Docusaurus](https://docusaurus.io/) и находится в каталоге `website/` репозитория [cpr1c/tools_ui_1c](https://github.com/cpr1c/tools_ui_1c).

## Требования

Перед началом работы убедитесь, что установлено:

| Компонент | Версия | Ссылка |
| --------- | ------ | ------ |
| Node.js | >= 20.0 | [nodejs.org](https://nodejs.org/) |
| npm | поставляется с Node.js | — |
| Git | любая | [git-scm.com](https://git-scm.com/downloads) |

Проверить установку:

```bash
node --version   # >=20.0
npm --version
git --version
```

## Быстрый старт

```bash
git clone https://github.com/cpr1c/tools_ui_1c.git
cd tools_ui_1c/website
npm install
npm start
```

Сайт откроется на `http://localhost:3000`. Любые изменения в `website/docs/` и `website/src/pages/` подхватываются автоматически (hot reload).

## Структура репозитория

Исходный код инструментов находится в [cpr1c/tools_ui_1c](https://github.com/cpr1c/tools_ui_1c). Основные модули:

```
src/
├── Инструменты/                     # Основная проект Инструментов (EDT-проект)
├── Портативный/                     # Портативная версия (внешняя обработка)
└── builder/                         # Сборочные скрипты (OneScript)
    ├── build.os                     # Точка входа сборки
    ├── lib/                         # Сторонние библиотеки
    ├── Классы/                      # Классы OneScript
    ├── Модули/                      # Модули сборки
    └── Шаблоны/                     # Шаблоны для генерации
```

При описании нового инструмента в документации указывайте, какой обработчик (`DataProcessor`) или общий модуль (`CommonModule`) его реализует — это упростит навигацию по исходному коду.

Рядом с сайтом в репозитории находятся и другие каталоги:

- `docs/` — встроенная документация в формате 1С (для чтения в EDT)
- `build/` — артефакты сборки (готовая портативная обработка и исходники расширения)
- `plans/` — планы развития
- `website/` — сам сайт документации (Docusaurus)
- `src/` — исходный код (см. выше)

## Структура документации (сайт)

```
website/docs/
├── intro.mdx                  # Введение
├── api/                       # Программный интерфейс
├── guides/                    # Руководства (установка, отладка, сборка…)
├── tools/                     # Описания инструментов по разделам
├── examples/                  # Примеры использования
└── contributing/              # Документация для контрибьюторов
```

## Формат файлов

Документация пишется в формате **MDX** — Markdown с возможностью использовать JSX-компоненты.

```mdx
---
sidebar_position: 1
---

# Заголовок страницы

Обычный текст с **разметкой** Markdown.

## Подзаголовок

- список
- пунктов

:::tip
Совет для читателя
:::

:::warning
Важное предупреждение
:::
```

## Metadata (frontmatter)

Каждый MDX-файл начинается с блока `---`, где указываются:

| Поле | Описание |
| --- | --- |
| `sidebar_position` | Порядок в сайдбаре (1, 2, 3…) |
| `slug` | URL страницы (если не указан, формируется из пути) |
| `description` | Краткое описание для SEO |

## Где что писать

- **Новый инструмент** — создайте файл в соответствующем разделе `docs/tools/*/`, добавьте `_category_.json` для группировки
- **Руководство** — `docs/guides/` (установка, отладка, сборка, миграция и т.д.)
- **API** — `docs/api/`
- **Примеры** — `docs/examples/`

## Ссылки

Внутренние ссылки — без расширения `.mdx`, от корня `docs/`:

```mdx
[Установка](/docs/guides/installation)
[Консоль запросов](/docs/tools/development-tools/query-console)
```

Внешние ссылки — полный URL:

```mdx
[GitHub](https://github.com/cpr1c/tools_ui_1c)
```

## Изображения

Изображения кладите в `static/img/` (для этого сайта) или в `docs/contributing/` (рядом с файлом, как в оригинальном репозитории).

```mdx
![Описание](/img/logo.svg)
```

## Обновление сайдбара

Сайдбар настраивается в файле `sidebars.ts` в корне репозитория сайта. При добавлении новой страницы в существующую категорию (`autogenerated`) ничего менять не нужно. Для новой категории — добавьте запись вручную.

## Pull Request

1. Внесите изменения в соответствующую ветку
2. Проверьте сборку: `npm run build`
3. Откройте PR в `develop` репозитория [cpr1c/tools_ui_1c](https://github.com/cpr1c/tools_ui_1c)
4. После мержа сайт обновится автоматически

## Советы

- Придерживайтесь единого стиля заголовков (с заглавной буквы)
- Используйте `:::tip`, `:::warning`, `:::note` для выделения важной информации
- Для примеров кода 1С используйте язык `bsl` в блоках:
  ````mdx
  ```bsl
  Сообщить("Привет, мир!");
  ```
  ````
- Для bash-команд — `bash`
