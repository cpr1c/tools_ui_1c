# Количество объектов в базе

Таблица с количеством записей в таблицах справочников, документов, регистров.

## Назначение

- Анализ объема данных в базе
- Выявление больших таблиц
- Планирование оптимизации

## Особенности

- Автоматический подсчет для всех объектов
- Сортировка по количеству записей
- Экспорт результатов

## Использование

1. Перейдите в меню **Универсальные инструменты → Количество объектов в базе**
2. Нажмите **Подсчитать**
3. Посмотрите результаты
4. Экспортируйте при необходимости

## Возможности

## Основные возможности

- **Автоматический подсчёт записей** — получение количества элементов для всех справочников, документов и регистров конфигурации.
- **Сортировка по количеству** — упорядочивание таблиц от наибольшего к наименьшему объёму данных.
- **Экспорт результатов** — выгрузка таблицы с количеством записей в табличный документ.
- **Группировка по типу** — отдельные разделы для справочников, документов, регистров.

## Дополнительные возможности

- **Быстрая оценка объёма базы данных** — анализ заполненности таблиц.
- **Выявление больших таблиц** — обнаружение объектов с наибольшим количеством записей.
- **Планирование оптимизации** — принятие решений об архивации или очистке данных.
- **Фильтрация по виду** — просмотр только справочников, только документов или только регистров.

## Сценарии использования

- Аудит объёма данных перед обновлением конфигурации.
- Поиск «разросшихся» регистров для оптимизации.
- Подготовка отчётности для администратора базы данных.
- Оценка необходимости индексации или очистки.

## Использование

## Быстрый старт

1. Перейдите в меню **Универсальные инструменты → Количество объектов в базе**.
2. Выберите вид объектов для подсчёта: справочники, документы, регистры или все.
3. Нажмите **Подсчитать**.
4. Просмотрите результат — таблицу с количеством записей по каждому объекту.

## Сценарии

### Подсчёт количества по всем объектам

```bsl
// Программный аналог расчёта количества
Для Каждого МД Из Метаданные.Справочники Цикл
    Запрос = Новый Запрос;
    Запрос.Текст = "ВЫБРАТЬ КОЛИЧЕСТВО(*) КАК Кол FROM " + МД.ПолноеИмя();
    Результат = Запрос.Выполнить().Выбрать();
    Если Результат.Следующий() Тогда
        Сообщить(МД.Имя + ": " + Результат.Кол);
    КонецЕсли;

```

## Часто задаваемые вопросы

## Общие вопросы

### Какие объекты учитываются?

Справочники (все элементы, включая группы), документы (все, включая непроведённые), регистры сведений, накопления, бухгалтерии, расчёта.

### Как быстро выполняется подсчёт?

Время зависит от объёма базы. Для баз с миллионами записей подсчёт может занять несколько минут. Ограничьте выборку по типу объектов.

### Можно ли увидеть только справочники?

Да, на форме обработки есть переключатель вида объектов: «Справочники», «Документы», «Регистры» или «Все».

### Влияет ли подсчёт на производительность базы?

Подсчёт выполняется запросами к базе данных и создаёт кратковременную нагрузку. Рекомендуется выполнять в нерабочее время для больших баз.

### Можно ли выгрузить результаты в Excel?

Да, результаты можно экспортировать в табличный документ (MXL, XLSX) через кнопку «Выгрузить».

### Что делать, если результат слишком большой?

Используйте сортировку по убыванию — вы увидите наиболее объёмные таблицы в начале списка.

### Учитываются ли помеченные на удаление объекты?

Да, в подсчёте участвуют все записи, включая помеченные на удаление.

## Решение проблем

## Проблемы

### Подсчёт зависает или выполняется слишком долго

Для баз с большим количеством записей время подсчёта может быть значительным. Начните с подсчёта только справочников или только документов. Используйте фильтр по конкретным объектам.

### Ошибка «Недостаточно памяти» при подсчёте

Обработка не загружает все записи в память — подсчёт выполняется на стороне СУБД. Если ошибка возникает, проверьте настройки сервера 1С и СУБД.

### Результат не обновляется

Нажмите кнопку «Подсчитать» повторно. Если данные не изменились, но результат старый, возможно, включено кэширование на уровне платформы.

### Некоторые объекты отсутствуют в списке

Проверьте, что объекты существуют в метаданных. Некоторые регистры могут быть пустыми — они отображаются с нулевым количеством.

### Ошибка при выполнении запроса для регистра

Если регистр содержит периодические реквизиты или имеет сложную структуру, запрос КОЛИЧЕСТВО(*) может выполняться дольше. Это нормальное поведение.

### Не совпадает количество с данными из конфигуратора

Платформа 1С может по-разному считать записи в разрезе виртуальных таблиц. Используйте прямые таблицы регистров для точного подсчёта.
