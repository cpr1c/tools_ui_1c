# Консоль веб-сервисов

Чтение и выполнение веб-сервисов, аналог soapUI. Форк [WSReader2](https://github.com/ghostaz/WSReader2) с разрешения авторов.

## Назначение

- Просмотр и тестирование веб-сервисов 1С
- Выполнение запросов к веб-сервисам
- Анализ SOAP-сообщений

## Особенности

- Автоматическое чтение WSDL
- Поддержка SOAP 1.1 и 1.2
- Возможность сохранения запросов и ответов

## Использование

1. Перейдите в меню **Универсальные инструменты → Консоль веб-сервисов**
2. Укажите URL веб-сервиса (WSDL)
3. Выберите необходимый метод
4. Заполните параметры и выполните запрос

## Возможности

## Основные возможности

- **Автоматическое чтение WSDL** — загрузка описания веб-сервиса по URL, парсинг всех доступных операций и типов данных.
- **Поддержка SOAP 1.1 и 1.2** — работа с обеими версиями протокола SOAP, автоматический выбор версии на основе WSDL.
- **Формирование SOAP-запросов** — автоматическая генерация XML-тела запроса на основе WSDL-описания.
- **Просмотр SOAP-ответов** — форматированный вывод XML-ответа с возможностью навигации по структуре.
- **Сохранение запросов и ответов** — возможность сохранить примеры запросов и полученные ответы для документации.

## Дополнительные возможности

- **Поддержка сложных типов** — работа со вложенными элементами, массивами и перечислениями.
- **Работа с заголовками SOAP** — добавление кастомных SOAP-заголовков (Security, Routing и др.).
- **Аутентификация** — поддержка Basic Auth, WS-Security, сертификатов.
- **Импорт/экспорт** — сохранение проектов в XML для последующего использования.

## Интеграция

- Для отладки HTTP-части SOAP-запросов можно использовать [Консоль HTTP-запросов](/docs/tools/development-tools/http-console).
- Ответы веб-сервисов можно обрабатывать в [Консоли кода](/docs/tools/development-tools/code-console).
- Инструмент является аналогом soapUI для 1С.

## Использование

## Быстрый старт

1. Откройте меню **Универсальные инструменты → Консоль веб-сервисов**.
2. Введите URL WSDL-документа веб-сервиса.
3. Нажмите **Загрузить** — инструмент прочитает WSDL и отобразит список доступных операций.
4. Выберите операцию и заполните параметры.
5. Нажмите **Выполнить** — SOAP-запрос будет отправлен, ответ отобразится в панели результатов.

## Сценарии использования

### Сценарий 1: Тестирование веб-сервиса 1С

1. Откройте публикацию веб-сервиса 1С, например: `http://server/base/ws/MyWebService?wsdl`.
2. Загрузите WSDL — список операций будет заполнен автоматически.
3. Выберите операцию, например `GetData`.
4. Заполните параметры: `Id = "123"`, `Date = "2026-06-18"`.
5. Выполните запрос.
6. Проанализируйте SOAP-ответ:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <GetDataResponse>
      <Result>
        <Name>Товар 1</Name>
        <Price>1500.00</Price>
      </Result>
    </GetDataResponse>
  </soap:Body>
</soap:Envelope>
```

### Сценарий 2: Отладка ошибок веб-сервиса

При получении SOAP Fault консоль отображает подробную информацию об ошибке:

```xml
<soap:Fault>
  <faultcode>soap:Server</faultcode>
  <faultstring>Ошибка выполнения операции</faultstring>
  <detail>
    <error>Параметр Id не может быть пустым</error>
  </detail>
</soap:Fault>
```

## Часто задаваемые вопросы

## Общие вопросы

### Какие форматы WSDL поддерживаются?
Поддерживаются WSDL 1.1 и WSDL 2.0, а также все распространённые binding-стили: document/literal, rpc/literal, rpc/encoded.

### Можно ли тестировать веб-сервисы без WSDL?
Да, можно вручную сформировать SOAP-запрос и отправить его через Консоль веб-сервисов или [Консоль HTTP-запросов](/docs/tools/development-tools/http-console).

### Сохраняются ли выполненные запросы?
Да, история запросов сохраняется. Можно также сохранить запрос как отдельный файл для повторного использования.

## Технические вопросы

### Что делать, если WSDL не загружается?
Проверьте доступность URL через браузер. Возможно, сервер требует аутентификации — укажите логин и пароль в настройках. Также проверьте, что сервер не блокирует запросы.

### Почему в ответе пустой SOAP-Envelope?
Возможно, веб-сервис не обнаружил ошибки, но и не вернул данных. Проверьте параметры запроса. Если метод ничего не возвращает (void), это нормальное поведение.

### Как передать файл через веб-сервис?
Используйте base64-кодирование. Включите содержимое файла в виде base64-строки в соответствующий элемент SOAP-запроса.

### Поддерживается ли WS-Security?
Да, базовая поддержка WS-Security (UsernameToken) реализована через настройки аутентификации.

## Решение проблем

## Проблема: WSDL не загружается, ошибка «Неверный формат WSDL»
**Причина:** WSDL-документ повреждён, содержит ошибки XML или использует неподдерживаемые расширения.
**Решение:** Проверьте WSDL через онлайн-валидатор. Убедитесь, что все импортированные схемы (XSD) доступны по указанным URL.

## Проблема: Ошибка «SOAP Fault: Server was unable to process request»
**Причина:** На стороне сервера произошла ошибка при обработке запроса.
**Решение:** Проверьте SOAP-запрос на корректность. Убедитесь, что все обязательные параметры заполнены. Просмотрите логи сервера для получения детальной диагностики.

## Проблема: Пустой ответ от сервера
**Причина:** Сервер не вернул SOAP-ответ (HTTP 202 Accepted или пустое тело).
**Решение:** Проверьте, что метод веб-сервиса действительно возвращает данные. Для методов с типом возврата void пустой ответ — штатное поведение.

## Проблема: Ошибка аутентификации при вызове веб-сервиса
**Причина:** Неверные учётные данные или отсутствует необходимый заголовок безопасности.
**Решение:** Проверьте логин и пароль. Для WS-Security добавьте соответствующий заголовок в SOAP-Envelope.

## Проблема: Несоответствие версий SOAP
**Причина:** Клиент использует SOAP 1.1, а сервер ожидает SOAP 1.2, или наоборот.
**Решение:** Убедитесь, что версия SOAP в запросе соответствует версии, указанной в WSDL (проверьте пространства имён `soap:`).
