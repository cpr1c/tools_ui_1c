# Консоль HTTP-запросов

Выполнение HTTP-запросов из 1С без создания внешних обработок. Удобный инструмент для тестирования веб-сервисов и API.

## Назначение

- Тестирование HTTP-запросов и веб-сервисов
- Быстрая отладка HTTP-взаимодействий
- Проверка ответов от внешних сервисов

## Особенности

- Поддержка всех методов HTTP (GET, POST, PUT, DELETE и др.)
- Настройка заголовков и тела запроса
- Просмотр кода ответа и заголовков

## Использование

1. Перейдите в меню **Универсальные инструменты → Консоль HTTP-запросов**
2. Укажите URL и метод запроса
3. Настройте заголовки и тело запроса (если нужно)
4. Нажмите **Выполнить** и посмотрите результат

## Примеры

```1c
// Пример GET-запроса
HTTPЗапрос = Новый HTTPЗапрос;
HTTPЗапрос.УстановитьТелоИзСтроки("");
HTTPЗапрос.Заголовки.Вставить("Content-Type", "application/json");
```

## Возможности

## Основные возможности

- **Поддержка всех методов HTTP** — GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS.
- **Настройка заголовков** — добавление произвольных HTTP-заголовков (Content-Type, Authorization, Cookie и др.).
- **Формирование тела запроса** — поддержка форматов JSON, XML, текста и произвольных данных.
- **Просмотр ответа** — отображение кода статуса, заголовков ответа и тела ответа.
- **Сохранение шаблонов запросов** — возможность сохранять часто используемые запросы.

## Дополнительные возможности

- **Работа с cookies** — автоматическая обработка Cookie, поддержка сессий.
- **Аутентификация** — поддержка Basic Auth, Bearer Token, NTLM.
- **История запросов** — автоматическое сохранение отправленных запросов с возможностью повторного вызова.
- **Переменные и окружения** — подстановка значений через шаблоны `{{переменная}}`.

## Интеграция

- Результаты HTTP-запросов можно обработать в [Консоли кода](/docs/tools/development-tools/code-console).
- JSON-ответы удобно просматривать в [Редакторе JSON](/docs/tools/development-tools/json-editor).
- Для работы с SOAP-сервисами используйте [Консоль веб-сервисов](/docs/tools/development-tools/web-service-console).

## Использование

## Быстрый старт

1. Откройте меню **Универсальные инструменты → Консоль HTTP-запросов**.
2. Укажите URL эндпоинта.
3. Выберите метод HTTP (GET, POST и т.д.).
4. При необходимости настройте заголовки и тело запроса.
5. Нажмите **Выполнить** и просмотрите ответ.

## Сценарии использования

### Сценарий 1: GET-запрос к REST API

```
GET https://api.example.com/v1/products
Headers:
  Accept: application/json
  Authorization: Bearer {{token}}
```

Ответ будет отображён в панели результатов. JSON можно скопировать в [Редактор JSON](/docs/tools/development-tools/json-editor) для анализа.

### Сценарий 2: POST-запрос с JSON-телом

```
POST https://api.example.com/v1/orders
Headers:
  Content-Type: application/json
  Authorization: Bearer {{token}}

Body:
{
    "customer_id": "12345",
    "items": [
        {"product_id": "ABC", "quantity": 2},
        {"product_id": "XYZ", "quantity": 1}
    ],
    "delivery_date": "2026-07-01"
}
```

### Сценарий 3: Работа с веб-хуками

Проверка входящего веб-хука от внешней системы:

```
POST https://hook.example.com/payment
Headers:
  Content-Type: application/x-www-form-urlencoded

Body:
event=payment.completed&order_id=ORD-2026-001&amount=1500.00
```

После выполнения проверьте код ответа — `200 OK` означает успешный приём.

## Часто задаваемые вопросы

## Общие вопросы

### Какие методы HTTP поддерживаются?
GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS. Любой метод можно указать вручную в поле ввода.

### Можно ли отправлять запросы с самоподписанным SSL-сертификатом?
Да. Если сертификат невалидный, появится предупреждение, но выполнение запроса не блокируется. При необходимости отключите проверку SSL в настройках.

### Сохраняется ли история запросов?
Да, все запросы автоматически сохраняются с указанием URL, метода и времени выполнения.

## Технические вопросы

### Как передать Basic-аутентификацию?
Добавьте заголовок `Authorization: Basic base64(login:password)` или воспользуйтесь встроенной формой ввода логина и пароля в интерфейсе.

### Почему приходит ответ с кодом 400?
Ошибка 400 Bad Request означает, что сервер не понял запрос. Проверьте правильность URL, формат тела запроса и обязательные заголовки.

### Как отправить запрос с файлом (multipart/form-data)?
Добавьте заголовок `Content-Type: multipart/form-data` и сформируйте тело запроса в соответствующем формате. Можно также использовать конструктор формы в интерфейсе.

### Работает ли консоль с прокси-серверами?
Да, HTTP-консоль использует системные настройки прокси, указанные в конфигурации 1С.

## Решение проблем

## Проблема: Ошибка «Не удалось разрешить DNS-имя»
**Причина:** Указан неверный URL или DNS-сервер недоступен.
**Решение:** Проверьте URL на наличие опечаток. Попробуйте выполнить запрос через браузер с тем же адресом. Убедитесь, что интернет-соединение активно.

## Проблема: Ошибка «Превышен таймаут ожидания»
**Причина:** Сервер не отвечает в течение установленного времени.
**Решение:** Увеличьте таймаут в настройках консоли. Проверьте доступность сервера (ping, telnet). Возможно, сервер перегружен или заблокирован фаерволом.

## Проблема: Ответ приходит в закодированном виде
**Причина:** Сервер прислал сжатый ответ (gzip, deflate).
**Решение:** Добавьте заголовок `Accept-Encoding: identity` для отключения сжатия. Консоль автоматически распаковывает gzip-ответы, если заголовок `Content-Encoding` указан корректно.

## Проблема: Ошибка 401 Unauthorized
**Причина:** Отсутствует или неверный токен аутентификации.
**Решение:** Проверьте заголовок Authorization. Обновите токен, если он истёк. Для Bearer-токенов укажите `Authorization: Bearer <токен>`.

## Проблема: Ошибка 403 Forbidden
**Причина:** Доступ к ресурсу запрещён для текущего пользователя.
**Решение:** Проверьте права на стороне сервера. Убедитесь, что используемый API-ключ имеет доступ к запрашиваемому эндпоинту.
